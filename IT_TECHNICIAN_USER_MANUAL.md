## 1. Getting Started

### What Can IT Technicians Do?

As an IT technician, your primary responsibilities in the system are:

- **View all system tickets** - See tickets from all departments and users
- **Assign tickets to yourself** - Accept tickets you want to work on
- **Update ticket status** - Change status from Open to In Progress to Resolved
- **Add technical comments** - Document what you've done and what you found
- **Update equipment status** - Mark equipment as repaired, in maintenance, etc.
- **Create repair tickets** - Generate repair logs for equipment issues
- **Track repair duration** - Monitor time from supervisor approval to completion
- **View repair history** - See all previous repairs for equipment
- **Access repair logs** - Document detailed repair information
- **View technician dashboard** - See your performance metrics
- **Report equipment issues** - Document equipment conditions and problems
- **Request escalation** - Escalate complex issues to management

### What Can't IT Technicians Do?

IT Technicians cannot:
- Create user accounts (only administrators can)
- Approve or deny tickets (only supervisors can)
- Change system settings
- Access other departments' restricted data
- Modify user roles or permissions
- Delete tickets or permanent remove data
- View audit logs (only administrators can)
- Change another technician's completed ticket status

## 2. Logging In

### First Time Login

1. Open your web browser and navigate to the IT Help Desk System URL
2. You will see the login page
3. Enter your technician username provided by your IT administrator
4. Enter your initial password
5. Click the **Login** button
6. You will be prompted to change your password
7. Enter a new password (at least 8 characters, mix of letters/numbers)
8. Confirm the new password
9. Click **Change Password**
10. You will see the IT Technician Dashboard
11. You are now ready to start working on tickets

### Subsequent Logins

1. Navigate to the login page
2. Enter your username
3. Enter your password
4. Click **Login**
5. You will be taken to the Technician Dashboard

### Forgot Your Password?

1. Click **Forgot Password?** on login page
2. Enter your email or username
3. Click **Reset Password**
4. Check your email for reset link
5. Click the link in the email
6. Enter new password
7. Confirm password
8. Click **Save New Password**
9. You can now log in with new password

### Tips for Logging In

- Always use your official technician username
- Passwords are case sensitive
- Change password every 90 days
- Do not share your password
- Log out when finished, especially on shared computers
- Clear browser cache if you have login issues

## 3. Understanding the Ticket System

### Ticket Workflow Overview

The ticket system follows this workflow:

1. **Created** - User submits ticket
2. **Open** - Ticket waiting for technician
3. **Awaiting Approval** - Supervisor reviews (if required)
4. **Approved** - Supervisor has approved the ticket
5. **Assigned** - Ticket assigned to technician
6. **In Progress** - Technician is actively working
7. **Resolved** - Technician has fixed the issue
8. **Closed** - User confirmed fix, ticket archived

### Your Role in Ticket Resolution

As an IT technician, you:

1. **Select tickets** from the queue
2. **Assign them to yourself** (indicate you're working on it)
3. **Update status** to show progress
4. **Document your work** with comments and details
5. **Resolve the issue** and mark as resolved
6. **Request confirmation** from user that fix works
7. **Close the ticket** when confirmed
8. **Track the duration** from approval to completion

### Understanding Ticket Duration Tracking

The system tracks several important time metrics:

- **Created Time** - When user submitted the ticket
- **Approval Time** - When supervisor approved the ticket
- **Assignment Time** - When you accepted the ticket
- **Start Time** - When you began working on it
- **Completion Time** - When you finished and resolved it
- **Closed Time** - When ticket was officially closed
- **Total Duration** - From supervisor approval to completion
- **Your Duration** - Time you spent working on it
- **SLA Target** - Expected resolution time
- **SLA Status** - Whether you met the target time

## 4. Viewing and Managing Tickets

### Accessing Ticket Queue

1. Click on **Tickets** in the left navigation menu
2. You will see the Ticket Queue
3. This shows all open and assigned tickets
4. Tickets are sorted by priority (urgent first)
5. You can filter by status, priority, category

### Viewing All Available Tickets

1. Go to **Tickets** → **Available Tickets** or **Open Queue**
2. You see tickets not yet assigned to anyone
3. List shows:
   - Ticket ID
   - Title
   - Priority
   - Category
   - Created Date
   - Department
   - User Name

### Filtering and Searching Tickets

To find specific tickets:

1. Use **Filter** options:
   - **Priority** - Urgent, High, Medium, Low
   - **Category** - Hardware, Software, Network, Other
   - **Department** - Show tickets from specific department
   - **Date Range** - Tickets created in specific period
   - **Status** - Open, In Progress, Resolved, etc.

2. Use **Search** bar:
   - Search by ticket ID
   - Search by user name
   - Search by title
   - Search by keywords in description

3. Click on column headers to sort:
   - Newest first
   - Oldest first
   - High priority first
   - By department

### Understanding Ticket Details

When you open a ticket, you see:

- **Ticket ID** - Unique identifier
- **Title** - Brief description
- **Priority** - Urgency level
- **Category** - Type of issue
- **Status** - Current state
- **Created By** - Who submitted it
- **Department** - Which department
- **Description** - Full details
- **Timeline** - All dates and times
  - Created Time
  - Approval Time (if supervisor approved)
  - Assignment Time
  - Your Start Time
  - Expected Completion Time
- **Comments** - All updates and notes
- **Assigned To** - Current technician (you if assigned to you)

## 5. Assigning and Accepting Tickets

### Assigning Tickets to Yourself

1. Go to **Tickets** → **Available Queue**
2. Find a ticket you want to work on
3. Click on the ticket to open it
4. Look for **Assign to Me** or **Accept** button
5. Click it
6. System asks you to confirm
7. Click **Confirm Assignment**
8. You are now assigned to the ticket
9. Status changes to your name as assigned technician
10. You receive a notification

### Accepting Ticket Assignment

If a ticket is already assigned to you:

1. Go to **My Tickets** or **Assigned to Me**
2. You see all tickets assigned to you
3. Click on ticket to open it
4. Click **Start Work** or **Begin Working**
5. Status changes to **In Progress**
6. Timer starts for your duration
7. You're now working on the ticket

### Understanding Assignment Duration

The system tracks time from when supervisor approves until you complete the fix:

- **Approval Time** - When supervisor approved the ticket
- **Your Assignment Time** - When you accepted the ticket
- **Duration to Assignment** - Time from approval until you accepted
- **Your Start Time** - When you began actual work
- **Duration to Start** - Time from approval until you started working
- **Completion Time** - When you resolved the issue
- **Total Duration** - Time from approval until resolution
- **SLA Target Duration** - Expected time to resolve (varies by priority)
- **Duration Status** - Whether you're on track, at risk, or exceeded SLA

Example:
- Ticket approved: 9:00 AM
- You assigned: 9:15 AM (Approval to Assignment: 15 minutes)
- You started work: 9:20 AM (Approval to Start: 20 minutes)
- Issue resolved: 10:30 AM (Approval to Completion: 1 hour 30 minutes)
- SLA Target: 2 hours (Status: ON TRACK)

### Viewing Your Workload

1. Go to **My Tickets** or **Dashboard**
2. You see tickets assigned to you
3. List shows:
   - **In Progress** - Tickets you're currently working on
   - **Pending Assignment** - Tickets waiting for you to start
   - **Resolved** - Tickets you've fixed (awaiting closure)
   - **Completed Today** - How many you finished today
4. You can see total time spent on each ticket
5. Shows how much longer until SLA deadline

## 6. Working on Tickets

### Starting Work on a Ticket

1. Open ticket assigned to you
2. Click **Start Work** or **Begin Working** button
3. System records your start time
4. Status changes to **In Progress**
5. A timer begins tracking your duration
6. You can now work on the issue
7. Update status as you make progress

### Updating Ticket Status (In Progress)

As you work on the ticket:

1. Open the ticket
2. Look for **Status** field
3. Change to **In Progress** when you begin
4. As you work, you can update:
   - **Investigating** - Diagnosing the problem
   - **Working on Fix** - Actively fixing
   - **Testing** - Testing the solution
   - **Waiting for User** - Waiting for user to test or respond
   - **Waiting for Parts** - Waiting for equipment or parts
5. Each status change is recorded with timestamp
6. Duration timer continues running

### Adding Technical Comments

1. Open the ticket
2. Scroll to **Comments** or **Updates** section
3. Click **Add Comment**
4. Type your update:
   - What you've discovered
   - What you've done
   - Progress made
   - Next steps
5. Click **Add Comment**
6. Comment is visible to user and supervisor
7. Timestamp shows when added

Example comments:
- "Inspected computer. Hard drive making clicking sounds. Likely drive failure."
- "Started recovery of data from hard drive before replacement."
- "Waiting for replacement hard drive to arrive. Should be here by tomorrow."
- "Replaced hard drive. Installing operating system now."
- "Installation complete. Running diagnostic tests."

### Providing Updates to Users

Users need to know what's happening:

1. Add comments regularly
2. Be specific about progress
3. Give time estimates when possible
4. Explain what you found
5. Explain what needs to happen next
6. Ask if they have questions

Good update: "Found a corrupted driver causing the crashes. Currently rolling back to previous version. Should have this fixed within 30 minutes."

Bad update: "Working on it."

### Estimated Time to Resolution

1. When you start working, estimate how long it will take
2. Click **Estimated Completion Time**
3. Select or enter a time
4. This helps user and supervisor know when to expect resolution
5. Update estimate if it changes
6. Common estimates:
   - Simple software issue: 15-30 minutes
   - Hardware diagnosis: 30-60 minutes
   - Hardware replacement: 1-2 hours
   - Complex issues: longer depending on nature

## 7. Tracking Approval to Completion Duration

### Understanding Duration Metrics

The system automatically tracks several time metrics:

**Key Duration Points:**

1. **Ticket Created** - User submits ticket (9:00 AM)
2. **Supervisor Approval** - Supervisor approves work (9:30 AM)
3. **You Assignment** - You accept the ticket (9:45 AM)
4. **You Start** - You begin work (10:00 AM)
5. **Issue Resolved** - You fix the problem (11:30 AM)
6. **User Confirmation** - User confirms it's fixed (12:00 PM)
7. **Ticket Closed** - Ticket archived (12:00 PM)

**Calculated Durations:**

- **Approval to Assignment**: 9:30 to 9:45 = 15 minutes
- **Approval to Start**: 9:30 to 10:00 = 30 minutes
- **Approval to Resolution**: 9:30 to 11:30 = 2 hours ← **KEY METRIC**
- **Your Working Time**: 10:00 to 11:30 = 1 hour 30 minutes
- **Total Ticket Time**: 9:00 to 12:00 = 3 hours

### Supervisor Approval Time Tracking

Before you can work on the ticket:

1. User creates ticket
2. Ticket status: **Open** (waiting for approval)
3. Supervisor reviews the ticket
4. Supervisor approves or rejects
5. If approved: status becomes **Approved**
6. **Approval Time** is recorded in the system
7. This is your "start point" for SLA measurement
8. The timer for "Approval to Completion" begins now

### Your Repair Start Time

When you accept and start working:

1. You assign ticket to yourself
2. You click **Start Work**
3. System records your **Start Time**
4. Your duration timer begins
5. This measures how long YOU spend on it
6. Separate from approval-to-completion time

Example Dashboard View:
```
Ticket ID: TK-1234
Status: In Progress
Priority: High
Approved At: 09:30 AM (by Supervisor John Smith)
Your Start Time: 10:15 AM
Duration from Approval: 45 minutes so far
Your Working Duration: 15 minutes so far
Estimated Completion: 11:30 AM
SLA Target: 2 hours from approval
SLA Status: ON TRACK ✓
```

### Monitoring Time to Fix

As you work on the ticket:

1. Dashboard shows real-time duration
2. **Approval to Now** - How long since approval
3. **Your Time** - How long you've been working
4. **Time Remaining** - Until SLA deadline
5. Color coded:
   - **Green** - On track, plenty of time
   - **Yellow** - Getting close to SLA
   - **Red** - Past SLA deadline

Example of time tracking on ticket detail:
```
TICKET DURATION TRACKING
─────────────────────────
Approved: 2026-06-08 09:30 AM (by Supervisor)
Your Assignment: 2026-06-08 09:45 AM (15 min to assign)
Your Start: 2026-06-08 10:00 AM (30 min to start)
Current Time: 2026-06-08 10:45 AM (45 min since approval)

YOUR WORKING TIME: 45 minutes
SLA TARGET: 2 hours (120 minutes)
TIME REMAINING: 1 hour 15 minutes
STATUS: ✓ ON TRACK
```

### Completion and SLA Compliance

When you fix the issue:

1. Click **Mark as Resolved**
2. System records completion time
3. Duration is calculated:
   - From approval to completion
   - Your working time
4. Compares to SLA target
5. Shows if you met SLA:
   - **ON TIME** - Completed within SLA
   - **DELAYED** - Completed after SLA
6. Ticket moves to "Resolved" status
7. Waiting for user confirmation
8. Duration details are saved for reporting

Example:
```
TICKET COMPLETED
────────────────
Approved: 9:30 AM
Resolved: 11:15 AM
Duration: 1 hour 45 minutes
SLA Target: 2 hours
Result: ✓ COMPLETED ON TIME (15 minutes early)
```

## 8. Managing Equipment Repairs

### Creating Repair Tickets for Equipment

When equipment needs repair:

1. Go to **Assets** → **Equipment**
2. Find the equipment
3. Click on it
4. Look for **Create Repair Ticket** button
5. Or go to **Tickets** → **Create New Ticket**
6. Select **Category**: Hardware (Repair)
7. Title: "Equipment Repair: [Equipment Name]"
8. Description: Describe the problem
9. Include asset code
10. Click **Create**
11. Ticket is created for tracking the repair

### Logging Repair Work

1. When assigned the repair ticket, start work
2. Document what you do:
   - What you inspected
   - What you found
   - What you replaced
   - What parts you used
   - Time spent
3. Add detailed comments
4. Update status as you progress
5. Record completion when done

### Tracking Equipment Condition

1. When working on equipment, assess condition
2. Open the equipment record
3. Click **Edit Condition**
4. Select current condition:
   - **Good** - Working properly
   - **Fair** - Working but may need maintenance
   - **Poor** - Needs repair soon
   - **Broken** - Not working, needs repair
5. Save the condition
6. This updates equipment status in system

### Recording Repair Time and Cost

After completing repair:

1. Open the equipment record
2. Go to **Maintenance History**
3. Click **Add Maintenance Record**
4. Enter:
   - **Date** - When repair was done
   - **Type** - Repair, Maintenance, Upgrade, etc.
   - **Description** - What was done
   - **Time Spent** - How many hours/minutes
   - **Cost** - If applicable (parts, labor)
   - **Technician** - Your name
   - **Status** - Completed, In Progress, etc.
5. Save the record
6. This creates equipment history for future reference

### Updating Equipment Status

1. After repair, update equipment status
2. Go to equipment details
3. Look for **Status** field
4. Update to:
   - **Active** - Equipment working, back in use
   - **In Maintenance** - Currently being repaired
   - **Awaiting Parts** - Waiting for replacement parts
   - **Disposed** - Equipment no longer usable
5. Save the status
6. Equipment status is updated in system

## 9. Closing and Resolving Tickets

### Marking Ticket as Resolved

When you've fixed the issue:

1. Open the ticket
2. Click **Mark as Resolved** button
3. The system records your completion time
4. Duration from approval to completion is calculated
5. SLA compliance is checked
6. Status changes to **Resolved**
7. Ticket is now awaiting user confirmation

### Requesting User Confirmation

After marking resolved:

1. Add a comment for the user
2. Explain what was fixed
3. Ask them to test it
4. Example: "I've replaced your hard drive and installed Windows 11. Please restart your computer and verify everything is working. Let me know if you experience any issues."
5. System automatically notifies the user
6. User tests the fix
7. User confirms it works

### Closing Tickets

Once user confirms the fix:

1. User or you can close the ticket
2. Click **Close Ticket** button
3. Final status is **Closed**
4. Ticket is archived
5. Final duration is recorded
6. Ticket appears in completed reports
7. Ticket no longer appears in active list

### Adding Resolution Comments

Before closing, add a final comment:

1. Summarize what was done
2. Explain the resolution
3. Include any notes for future reference
4. Example: "Replaced hard drive and installed OS. Ran full diagnostics - all tests passed. User confirmed system is working normally."
5. Click **Add Comment**

### Preventing Reopening

Once closed, ticket should not reopen:

1. If user has more issues, they should create a new ticket
2. Reference the original ticket in new one
3. Keep original ticket closed
4. This maintains accurate duration metrics
5. Shows how often same issue reoccurs

## 10. Common Technician Tasks

### Task: Accepting and Resolving Hardware Issue

**Scenario**: Ticket TK-5234 - "Computer won't start" - Priority HIGH - Approved at 10:00 AM

**Steps:**

1. Go to **Tickets** → **Available Queue**
2. Find ticket TK-5234
3. Click to open it
4. Click **Assign to Me**
5. Click **Confirm**
6. You're now assigned, status shows your name
7. Click **Start Work** - Records 10:15 AM start time
8. Add comment: "Arrived at office. Computer won't power on. Checking power cable and PSU."
9. You test the power supply
10. Add comment: "Found PSU is faulty. Ordering replacement from warehouse."
11. Update status: **Awaiting Parts**
12. Estimated completion: 2 hours (SLA target)
13. Parts arrive 30 minutes later
14. Add comment: "Replacement PSU arrived. Installing now."
15. Update status: **In Progress - Installation**
16. You replace the PSU
17. Computer starts successfully
18. You run diagnostics - all pass
19. Add comment: "PSU replacement complete. Computer starts normally. All diagnostics pass. Ready for user testing."
20. Click **Mark as Resolved**
21. **Duration from Approval to Resolution: 1 hour 45 minutes** ✓ ON TIME (SLA was 2 hours)
22. Notify user: "Computer is repaired and ready. Please restart it to confirm."
23. User confirms it works
24. You click **Close Ticket**
25. Dashboard shows:
    - Status: CLOSED
    - Repair Duration: 1h 45m
    - SLA: ON TIME
    - Your Working Time: 1h 45m

### Task: Diagnosing Software Problem

**Scenario**: Ticket TK-5235 - "Excel crashes when opening large files" - Priority MEDIUM - Approved at 2:00 PM

**Steps:**

1. Assign to yourself and start work (2:15 PM)
2. Add comment: "Starting troubleshooting. Will test Excel with progressively larger files."
3. You test with small file - works
4. You test with medium file - works
5. You test with large file - crashes
6. Add comment: "Narrowed down issue: Excel crashes with files over 50MB. Checking available memory and Excel version."
7. Check Excel version: 2019 (outdated)
8. Check available RAM: 4GB (limited)
9. Add comment: "Found two issues: Excel 2019 is outdated and system has limited RAM. Updating Excel to 2024 and checking RAM upgrade options."
10. Update Excel to latest version
11. Test with large file again - works
12. Add comment: "Excel update resolved the issue. Large files now open without crashing. User should also consider RAM upgrade for better performance."
13. Mark as **Resolved** (2:50 PM)
14. **Duration from Approval to Resolution: 50 minutes** ✓ ON TIME
15. Request user test: "I've updated your Excel to the latest version. Please test it with your large files to confirm it works."
16. User confirms fixed
17. Close ticket

## 11. Troubleshooting and Tools

### Common Hardware Issues

**Computer Won't Start**
- Check power cable and outlet
- Try force start (hold power button 30 seconds)
- Check power supply (listen for fan)
- Check motherboard lights
- If no lights, PSU likely faulty

**Computer Overheating**
- Check if vents are blocked
- Clean dust from fans
- Check if thermal paste is dry
- Consider thermal pads replacement
- Monitor temperature in BIOS

**Hard Drive Failure**
- Listen for clicking sounds
- Try connecting to external USB adapter
- Run diagnostics tool
- Attempt data recovery if needed
- Replace drive if failed

**RAM Issues**
- Computer won't start or random crashes
- Try reseating RAM modules
- Test one module at a time
- Replace suspected bad module
- Use memory diagnostic tool

**Monitor Problems**
- Check power and signal cables
- Try different input (HDMI, VGA, etc.)
- Test on different computer
- Check monitor settings/menu
- May need monitor replacement

### Common Software Issues

**Application Crashes**
- Update the application to latest version
- Reinstall if needed
- Check system compatibility
- Update graphics drivers
- Check available disk space and RAM

**Slow Performance**
- Run antivirus/malware scan
- Check Task Manager for resource hogs
- Clear temp files and cache
- Check startup programs
- Consider RAM upgrade or SSD

**Blue Screen (Windows)**
- Note the error code
- Update drivers, especially graphics
- Check for hardware issues
- Run Windows repair/reset
- Check system logs for error details

**Software License Issues**
- Verify license is active
- Check license expiration date
- Re-license if needed
- Contact vendor if license issue
- Update license database

### Network Troubleshooting

**No Internet Connection**
- Check router lights
- Restart modem and router
- Check WiFi signal strength
- Verify correct WiFi network
- Check IP configuration
- Ping gateway to test connectivity

**Slow Network**
- Check WiFi signal strength
- Run speed test
- Check for interference (2.4GHz WiFi)
- Check for bandwidth hogs
- Consider WiFi positioning
- Contact network team if systemic

**Can't Connect to Server**
- Verify server is online
- Check firewall rules
- Verify credentials
- Check network cables
- Run network diagnostics
- Check DNS resolution

### Remote Assistance Tools

For remote support (if configured):

1. Share your screen with user
2. Use remote control software (if authorized)
3. Provide verbal guidance
4. Have user perform steps
5. Watch for errors
6. Document what you find

### Knowledge Base Access

1. Go to **Help** → **Knowledge Base**
2. Search for known issues
3. Find solutions for common problems
4. Read detailed explanations
5. Follow step-by-step guides
6. Access from tickets when needed

### Escalation Procedures

When you can't resolve an issue:

1. Add a comment: "This issue requires specialized knowledge. Escalating."
2. Click **Escalate** button
3. Select escalation reason
4. Select who to escalate to (supervisor, manager, vendor)
5. Add details about what you've tried
6. System notifies supervisor/manager
7. Ticket moves to escalation queue
8. Don't close ticket - just escalate
9. You may continue assisting while escalated
